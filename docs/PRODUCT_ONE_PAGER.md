# create-video-knowledge-assets 视频知识资产 · 作品集一页纸

> 本页用于 30 秒快速了解这个项目：为什么做、怎么做、做出了什么。面试时建议按"一句话 → 一个痛点 → 一个设计 → 一个结果"的顺序讲。

## 一句话

**create-video-knowledge-assets 把一个知识视频，变成一套可直接交付、可复用、可追溯的视频内容成品。**

## 背景与痛点

高价值知识大量沉淀在视频里，但视频天然不适合快速复习、二次创作和团队共享。用户通常要反复回看、手工整理笔记、再整理成文——成本高，还容易漏掉关键逻辑、例子和边界条件。

这个项目不解决"把视频压缩成短摘要"，而是解决"把一次观看变成可持续利用的视频内容结果"。

## 产品做什么

输入一个 Bilibili 链接或本地知识视频，输出**deep-summary、deep-article、short-video-script、course-notes**四类主成品 profile。正文默认只交付一个干净成品，内部 provenance 保留在资产里。三种格式（PDF / HTML / Markdown）来自同一份 renderer-neutral 底稿，先沉淀知识，再由同一份底稿渲染，内容完全一致。

## 核心设计决策（为什么这样设计）

| 决策 | 人话解释 | 如果不这样做会怎样 |
| --- | --- | --- |
| **证据优先** | 每个结论都能溯源到视频的具体时间窗和画面；明确标注"视频说的"、"推断的"、"证据不足的" | 生成内容貌似完整，但无法核验，接近"看起来合理"的黑箱 |
| **知识与交付分离** | 先沉淀知识，再从同一份底稿导出成品 | 每种产出各写一遍，内容漂移、维护成本翻倍 |
| **一个资产多成品** | 一份规范资产，服务学习 / 创作 / 脚本 / 归档多种用途 | 每个场景都要重新理解一遍视频，成本随场景数线性增长 |
| **质量门与人工介入** | 关键步骤有校验和人工审阅点，不确定的内容降级标注而非硬补 | 全自动黑箱输出，事实和版权风险失控 |

## 做出的结果

- **端到端可用**：2 个真实 Bilibili 视频完成从 URL、转录、抽帧检查、知识建模到 PDF 交付的完整链路（见 [README Demo 区](../README.md#真实成果)）。
- **工程可靠**：约 1.1 万行 Python、28 个功能模块、31 个测试文件；**全套测试 477 项通过**，CI 双门禁（stable 阻断 + experimental 不阻断）。
- **契约化交付**：23 份 schema / 工作流 / 安全契约文档，让 Agent 的每一步都可被校验和追溯。
- **产品化思考**：从产品需求出发定义了北极星指标——"一份视频经过一次完整处理后，能否被直接拿去学习、汇报或再创作，而无需重听整段视频"。

## 我的角色

独立完成从产品需求（PRD）、架构设计、核心工程实现到质量验收的完整闭环。外部工具（yt-dlp / ffmpeg / Whisper / XeLaTeX）作为能力边界被调用，产品自己的证据模型、知识模型、业务视图与渲染链路由本仓库实现。
